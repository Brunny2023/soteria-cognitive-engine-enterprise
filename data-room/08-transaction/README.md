# 08 — Transaction

## What is included

Unless a signed agreement says otherwise, the proposed technical asset perimeter includes the source repository at the agreed commit, documentation, tests, migrations, deployment templates, release workflows, SBOM generation process, buyer-facing diligence documents, and the live-site screenshots included in this data room.

## What is not included by default

No credentials, customer data, private agreements, provider accounts, domain registrar account, cloud account, trademark ownership, undisclosed liabilities, revenue claim, production SLA, or external legal representation is included by merely transferring repository files.

## License options

Potential structures include:

| Structure                        | Buyer receives                                        | Key negotiation points                                        |
| -------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| Non-exclusive commercial license | Defined use, deployment, and modification rights      | Field, territory, term, support, sublicensing                 |
| Exclusive license                | Exclusive commercial use within a defined scope       | Reserved rights, enforcement, minimum commitments             |
| Asset acquisition                | Agreed source, documentation, and transferable rights | Chain of title, exclusions, representations, escrow           |
| Strategic integration            | Limited code and integration rights                   | Confidentiality, roadmap, services, ownership of improvements |

Counsel must convert the selected structure into a signed agreement.

## Asset transfer structure

Recommended sequence: diligence access; buyer technical validation; rights and dependency clearance; signed definitive agreement; credential rotation; repository/archive transfer; domain/brand transfer if included; buyer-controlled deployment; transition acceptance; support handoff.

## Transition and support options

Possible handoff packages include a documentation-only transfer, a fixed transition period, architecture walkthroughs, deployment assistance, issue triage, or paid implementation. No support commitment is made by this data room without a signed statement of work.

## Closing checklist

- Confirm exact commit and repository archive.
- Confirm included/excluded files and accounts.
- Complete IP assignments and contributor declarations.
- Rotate historical and current credentials before transfer.
- Complete dependency, model, media, domain, and trademark review.
- Agree license, consideration, escrow, indemnity, and support terms.
- Execute buyer staging deployment and blocked security tests.
- Record acceptance evidence and transfer authority.
