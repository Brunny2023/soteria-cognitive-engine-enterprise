# Ownership, Provenance, and Release Policy

The commercial distribution is maintained as an independent software product. Its source tree contains first-party domain modules, standard framework scaffolding, and third-party dependencies. The product must not be represented as free of third-party or hosted-service obligations.

The owner is accountable for release decisions, dependency updates, security fixes, and customer commitments. Published history must not be rewritten or force-pushed. Security-sensitive changes require review by an owner familiar with Supabase RLS, service-role boundaries, and governed AI tools.

The differentiated modules are the staged execution engine, constrained data tools, deterministic knowledge-graph rules, safe arithmetic, organization workflows, audit-integrity manifests, and Supabase migrations. Standard UI primitives and third-party libraries are not represented as proprietary differentiation without a corresponding license record.

A release requires a clean install, typecheck, lint, tests, migration checks, security checks, production build, current threat model, operations evidence, reference-workflow evaluation, SBOM, and third-party rights schedule. Contributor IP assignments and dependency/model/provider terms must be complete before a transfer or enterprise contract.
