# IP and Provenance Dossier

**Purpose:** Record the provenance facts and unresolved rights questions that a buyer must review before commercial transfer. This file contains no credentials, private contracts, personal addresses, or confidential legal evidence.

## First-party product scope

The Soteria software scope includes the domain modules under `src/lib/`, route and UI composition under `src/routes/` and `src/components/`, Supabase migrations under `supabase/migrations/`, release and evaluation scripts under `scripts/` and `evaluations/`, deployment templates under `infra/`, and engineering documentation under `docs/`.

The most commercially material modules are the staged execution flow, scoped SQL and tool adapters, organization and membership functions, deterministic knowledge and metric rules, audit-integrity functions, telemetry redaction, and the migration set that defines tenant and role boundaries.

## Contributor and history record

The repository history must be preserved for diligence. The reviewed history contains approximately 213 commits. The local history includes commits authored by the repository owner, Soteria-related identities, platform-related identities, and an automation bot identity. The current revision intentionally does not rewrite or falsify that history.

The history contains platform provenance markers, including `X-Lovable-Edit-ID` metadata and commits authored by `gpt-engineer-app[bot]`. These facts are not included in product marketing language, but they remain relevant to chain-of-title diligence.

The seller must obtain and retain, outside this public source tree where appropriate:

1. Signed contributor and contractor intellectual-property assignments.
2. Confidentiality and invention-assignment records where applicable.
3. Written confirmation of the rights governing platform-generated or platform-edited application code and AI output.
4. A record of which contributors had authority to commit or approve changes.
5. A statement that no customer confidential information or production secrets are included in the transferred tree.

## Dependencies and hosted services

The npm dependency set is locked in `package-lock.json` and a CycloneDX SBOM is generated by `npm run security:sbom`. A buyer must review each dependency’s license and preserve required notices. Supabase, the selected AI gateway/model provider, email provider, hosting provider, OAuth providers, and monitoring systems remain external services with independent terms.

The provider-neutral adapters do not transfer provider accounts, model licenses, customer data rights, or data-processing agreements. Those must be contracted or configured by the buyer.

## External assets

The repository includes public UI assets and demo media. Before commercial redistribution, the seller or buyer must inventory `public/` media, fonts, icons, screenshots, and any externally sourced content, then attach source and redistribution rights to the transaction data room. The repository makes no blanket representation that every external asset is transferable without review.

## Evaluation data and AI output

The committed evaluation fixture is synthetic and is intended to avoid customer data. Runtime AI output is environment-dependent and may be subject to the selected provider’s terms, retention rules, model license, and data-use policy. No customer prompt, proprietary knowledge base, or confidential model output should be added to this repository.

## Ownership assumptions requiring legal confirmation

The transaction should confirm that the seller owns or can transfer the first-party code, documentation, original media, configuration templates, and rights to commercialize any relevant AI output. It should separately identify third-party material that is only licensed for use and cannot be assigned. It should confirm that platform terms do not impose restrictions inconsistent with the proposed commercial license or source-code transfer.

## Unresolved questions

- Which individuals or entities executed written IP assignments for all material contributions?
- What rights and obligations apply to platform-generated or platform-edited portions of the history?
- Are all public demo videos, subtitle files, icons, fonts, and images cleared for commercial redistribution?
- Which third-party provider terms apply to the buyer’s selected model, email, hosting, and monitoring configuration?
- Does any historical branch, tag, artifact, or external storage contain secrets or customer information requiring rotation, deletion, or restricted transfer?
- Which final license and warranty language will counsel approve for the transaction?

## Evidence policy

This dossier is an index and issue register. Signed assignments, confidential agreements, provider contracts, and personal information must remain in a restricted transaction data room. Their absence from this repository is intentional and must not be interpreted as proof that the rights have been established.

The reviewed key names were limited to Supabase project, URL, and publishable-key variables; values were not printed or copied into this dossier.
